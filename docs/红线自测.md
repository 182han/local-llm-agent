## 附：`rubric.json` 三个 red flag 的自动化断言

`tests/test_smoke.py` 里有对应断言，`reproduce.sh` 第 7 步会跑：

| Red flag | 对应断言 |
|---|---|
| `missing_artifacts` | `六件套 7 个文件齐全且非空` / `C4D CHALLENGE.md 的 8 项交付物齐全` / `仓库通用文件齐全` |
| `no_ai_log` | `AI日志 ≥6 个决策节点，且包含 ollama pull 401 事故` / `AAR 覆盖七维且声明为自拟` |
| `one_shot_ai` | `诚实性：没有任何文件声称已截图/已发布/已发群` / `验证报告里的数字与机器可读结果一致` / `CHANGELOG 记录真实开发过程` |

### 最有力的那条断言

```python
# tests/test_smoke.py
def _():
    """验证报告里的 tok/s 必须与 bench.json 里的实测值逐位一致"""
    d = json.load(open(bench_json))
    val = d["prompts"]["short"]["server_tok_per_s_median"]
    assert f"{val:.2f}" in report_text, f"bench value {val:.2f} not quoted in the report"
```

**这条断言把"报告里的数字"钉死在"机器产出的数字"上**——
如果我在报告里写了一个好看但不存在的 tok/s，测试会红。
**这是防止"自己骗自己"的机制化手段。**
